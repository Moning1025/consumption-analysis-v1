## 这个系统解决什么问题

我做这个系统，起因是一个很具体的困惑：我想知道一个城市的消费到底怎么样，结果发现答案散在三个地方——商家在哪、卖什么，在高德的 POI 里；消费总量和增速，在统计局的月度指标里；而我自己能拿到的商家流水，是一堆格式各异的 Excel 表。三份数据地名写法不一样，时间粒度不一样，字段口径也不一样。我打开任何一份都只能看到一个角，拼不起来。

后来我又发现缺了两样东西：**这条街到底有多少人住、有多热闹**。没有人口，我只能数"这条街有 30 家火锅店"，但说不出"这 30 家店是服务 2 万人还是 8 万人"；没有灯光这种活力信号，我也分不清"店多"是因为需求旺还是因为过度竞争。所以我接入了两个公开遥感数据源——夜间灯光强度和百米人口栅格——**结合夜间灯光与人口密度，评估真实的市场潜力**，让"密度"第一次有了分母，让"活力"第一次有了尺子。

所以我做的是把这五份数据接进来、对齐、洗干净，存成一份能反复用的数据，再在它上面做分析：地域热力、RFM 分层、品类结构、趋势与异常、市场潜力。技术上就是在一台电脑上跑的东西——Python 采数据，Pandas 做清洗融合，SQLite 存本地、MySQL 做服务端版本，界面上能看到每个任务真实跑到哪一步。

它的用处不是图好看。真正想回答的是"为什么"：不是"这个月卖了多少"，而是"这个月比上月少的那部分，有多少来自某个区、某个品类、某个客群的下滑"。Excel 能算出总数，但拼不起五个口径——这就是区别。

### 给谁用、回答什么问题、靠哪几个维度回答

| 项 | 内容 |
|---|---|
| **目标用户** | ① 本地商家（单店/小连锁，想知道"我这店开得对不对、往哪挪/往哪扩"）② 商圈运营者（商场、街区运营方，想做业态配比与招商）③ 连锁品牌拓展部（要选址，看哪个城市哪个区还缺我这个品类） |
| **分析目标** | 回答一句话：**"在这个城市的这个地方，开什么店最赚钱，为什么？"** 不是"这个月卖了多少"这种汇总题 |
| **核心维度 1 · 空间匹配度** | 用**供给密度 vs 消费密度**找蓝海：某区某品类 POI 密度高但消费密度低 = 过度竞争（红海）；POI 密度低但消费密度高 = 供给缺口（蓝海）。这是"开什么店"的直接依据 |
| **核心维度 2 · 品类结构** | 该区域品类构成与全省/全市均值的偏离度——是餐饮独大还是零售补位，缺哪一类 |
| **核心维度 3 · 客群分层（RFM）** | 把客群按最近消费/频次/金额分层（内部算 8 类，界面默认归并为 5 层），看高价值客户集中在哪、流失风险在哪 |
| **核心维度 4 · 趋势与异常** | 月度趋势 + 异常点检测，回答"这个月比上月少的那部分，是普遍下滑还是某个区某个品类塌了" |
| **核心维度 5 · 市场潜力（人口 + 灯光）** | 每个 1 km 格网同时挂**人口分母**（WorldPop 百米栅格采样）与**夜间灯光强度**（VIIRS 年均产品采样）：人口给"密度"当分母（每万人 POI 数），灯光给"活力"当权重。于是能区分"店多且人多（饱和但有生意）"与"店多但人少（虚高泡沫）"——这是维度 1 从"数店铺"升级成"算需求缺口"的关键 |

> 这五个维度就是论文第 3 章"系统功能分析"和第 4 章"数据可视化"的骨架，也是答辩时"你的系统到底解决了什么"的标准答案。（2026-11-12 四维原始版；同日补第五维"市场潜力（人口 + 灯光）"）
