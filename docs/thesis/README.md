## 4. 图表与公式格式（模板实测摘录）

- **章节号是 Word 多级列表自动编号**（样式 `heading 1`），正文里没有手写的“第1章”字样——所以写作时不要手打章号，交给样式。
- 图题：模板第 3 章示例为 `图3.1E-R图`、`图3.12原型图`（**章.序号，无空格**）；第 5 章示例却混用了 `图5-1数据分析图`、`表5-1 测试用例表`。
- 表题：`表5-1 测试用例表`（序号后**有空格**再跟表名）。
- 公式编号：`(1-1)` 形式，编号随章。
- **结论**：模板自身不统一。建议全篇统一成一种，本项目推荐 `图3-1` / `表3-1`（连字符式，学长全文采用且通过答辩，且不会和“3.1 节”的小数点混淆）；若导师要求跟第 3 章示例，则统一 `图3.1`。**定稿前问一句导师，一次定死。**
- 图表一律“先文后图”：正文先说明“如图 X-Y 所示”，图在下、图题在图下方居中。

## 5. 结构判定

**这是一篇“重系统实现”的应用开发型论文**，不是算法研究型：

- 骨架是 需求分析 → 概要设计 → 详细设计 → 实现 → 测试（第 3、4、5 章占 6000~7500 字，是主体）。
- “算法”只出现在 3.3.2「模块2（数据分析）设计」这一个子节里，不独立成章。
- 对答辩的含义：老师会问“**你的系统做了什么、怎么测的**”，而不是“你的模型创新在哪”。所以第 5 章测试和 Demo 演示比任何算法都值钱。

## 6. 写作参考：学长论文的套路（≤200 字）

> 59 页，正文至 52 页；中文摘要约 450 字、英文约 300 词、关键词 5 个。六章，每章末尾必写“本章小结”。第 2 章按技术逐节平铺（爬虫/Django/MySQL/Pandas/sklearn/可视化各一节）；第 3 章先五问可行性、再功能模块图+用例图；第 4 章顺序为架构图→数据获取→处理→存储→E-R→建表图；第 5 章按模块讲实现并贴关键代码；第 6 章几乎全是测试用例表。图题用“图X-Y”，每千字约 1 图，行文重流程叙述、极少公式。

**可以直接借的**：每章小结、技术逐节平铺、数据来源一条线讲清“从哪来→怎么洗→存哪→怎么用”、用例图+E-R+建表图三件套、测试用表格化用例。
**不要借的**：七章结构（2026 已合并）、纯叙述不给数据（我们要贴真实行数/耗时）。

## 7. 写作顺序建议（和 ROADMAP 对齐）

第 1、2 章不依赖代码 → 现在就能写（第 2 章等 S3 的 Pandas 实测数据出来再补数字）。
第 3 章等 S2-2 的地域归一化设计定稿；第 4、5 章必须等对应阶段真跑通再写，否则写出来是空的。
