## 2.2 SQLite 与 MySQL 双后端

TODO
- 是什么：SQLite 单文件无服务嵌入式库；MySQL 客户端-服务端关系库。
- 为什么两个都要：毕设演示要“零安装可跑”（SQLite），答辩要“能讲清索引与执行计划”（MySQL）。
- 代价：SQL 方言差异（自增主键、日期函数、`ON DUPLICATE KEY` vs `ON CONFLICT`）→ 用一层数据访问接口隔开。
- 在本系统：`store/` 数据访问层 + 配置切换。

## 2.3 pywebview + 原生 JS + ECharts 桌面壳

TODO
- 是什么：pywebview 用系统 WebView 承载本地 HTML，Python 与 JS 通过 `js_api` 双向调用。
- 为什么选：比 Electron 轻（无 Node 运行时），比纯网页多一个“本地文件系统 + 数据库”的入口。
- 代价：前端不能直接 `fetch` 本地 API，只能走 `pywebview.api.*`；大屏图表库需离线化（当前 ECharts 走 CDN，是隐患）。
- 在本系统：`main.py` 建窗口、`bridge_api.py` 暴露方法、`web/index.html` 渲染。

## 2.4 异步任务与状态可观测

TODO
- 是什么：线程池 + 任务快照表（`job_run`）+ 事件日志表（`job_event`），前端按 `seq` 增量拉日志。
- 为什么需要：清洗是分钟级长任务，同步执行会冻界面；进度必须来自真实阶段推进，不能靠 sleep 推算。
- 代价：SQLite 单写者 → 所有写操作必须短事务；取消只能是协作式（置标志位，任务在阶段边界自查）。
- 在本系统：`pipeline/job_runner.py`、`store/job_store.py`。
